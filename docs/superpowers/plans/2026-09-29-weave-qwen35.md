**Goal:** 在 Docker 中运行完整 Qwen3.5-35B-A3B BF16，以 GPQA batch=1、thinking 开启、最多生成 32K（32768）tokens，对比同版本 SGLang 原生与自行实现 Weave 的真实 decode 速度。

**Architecture:** 共享 SGLang 的模型/服务运行时，自行编写 routed-MoE persistent megakernel 和动态调度，作为可切换后端接入。保留 attention、共享专家、缓存与采样语义。源码经 GitHub 同步，GPU 编译、正确性与性能验证由服务器执行并回传证据。

**Tech Stack:** Python、PyTorch C++/CUDA extension、Hopper BF16 Tensor Core、peer-access/CUDA IPC 与可审计的 ThunderKittens 原语、SGLang、Docker；CPU 数据准备使用已固定的 tokenizers/Jinja2。

**Spec:** `docs/superpowers/specs/2026-09-29-weave-qwen35-design.md`，执行前完整阅读。

## Global Constraints

- 模型：`/mnt/public_data/Qwen/Qwen3.5-35B-A3B`，BF16，无量化。
- 首轮：单机同一组 4×H100，EP=4；TP/DP/attention 布局从 baseline 采集并统一。
- 数据：GPQA Main，自然长度，batch=1、concurrency=1。
- 生成：thinking=true、max_new_tokens=32768、正常 EOS；初始 greedy，MTP/推测解码关闭。
- 对比模式只有 `sglang_native`、`weave_full`；两组使用同一 runtime commit、相同共享专家/graph/cache 策略。
- 每个 mode 在服务 ready 后预热+测量最多 1200 秒；构建与加载另计。
- 编码端无 GPU 服务器连接。所有 GPU 结果必须来自服务器真实执行，保留提交与环境指纹。
- 不增加其他模型、量化、基线、并发规模或人为 8K GPQA 性能实验。
- Weave 模式在 prefill 与 decode 都执行自行实现的 routed-MoE 后端。禁止静默 fallback 后输出名为 Weave 的性能结果。
- GPU 正确性测试必须先于正式性能比较；没有加速阈值不等于不需要正确性验证。

## 跨模块接口合同

在 Task 2 实现这些接口，后续任务使用相同名称。所有 tensor 位于调用 rank 的同一 CUDA device，shape 检查不得触发每层 CPU 同步。

```python
from dataclasses import dataclass
from typing import Literal
import torch

@dataclass(frozen=True)
class LayerWeights:
    gate_up: torch.Tensor  # BF16 [local_experts, 2*512, 2048]
    down: torch.Tensor     # BF16 [local_experts, 2048, 512]
    first_expert: int      # 0, 64, 128, 192 for EP=4
    gate_up_order: Literal["gate_then_up"]

@dataclass(frozen=True)
class RoutingInputs:
    hidden: torch.Tensor       # BF16 [local_unique_tokens, 2048]
    expert_ids: torch.Tensor   # int32 [local_unique_tokens, 8]
    weights: torch.Tensor      # FP32 [local_unique_tokens, 8], native normalized values
    origin_ids: torch.Tensor   # int32 [local_unique_tokens, 2]: (rank, index)

@dataclass(frozen=True)
class SchedulePlan:
    comm_workers: int
    chunks: int
    steal_tiles_per_worker: int

```

具体函数签名与实现任务如下。`RankWorkspace` 是 Task 3 实现的资源所有者类型，拥有 IPC 导出/导入、固定容量 buffers、计数器和 device epoch，`close() -> None` 按依赖顺序释放资源。

| 函数签名 | 负责实现 | 合同 |
|---|---|---|
| `create_workspace(max_tokens: int, group, device: torch.device) -> RankWorkspace` | Task 3 | 所有 rank 参与初始化，返回稳定地址的缓冲区所有者 |
| `load_layer_weights(native_experts, rank: int, ep_size: int) -> LayerWeights` | Task 2 | 初始化时重排本 rank 专家，保留明确 gate/up 顺序 |
| `reference_moe(inputs: RoutingInputs, all_expert_weights: LayerWeights) -> torch.Tensor` | Task 2 | 使用完整专家集合的数学参考，不执行分布式通信 |
| `weave_moe(inputs: RoutingInputs, weights: LayerWeights, workspace: RankWorkspace, layer_id: int) -> torch.Tensor` | Task 4/5 | Python wrapper 解包 tensor 给 custom op；返回原始本 rank unique token 顺序的 routed 输出 |
| `install_weave_backend(model, runtime_config: dict, baseline_lock: dict) -> dict` | Task 6 | 安装全部目标层，返回安装层数和可查询覆盖状态 |
| `validate_comparison_settings(native: dict, weave: dict) -> None` | Task 1 | 对照设置不一致时抛出包含字段名的 ValueError |
| `decode_metrics(output_tokens: int, first_token_s: float, last_token_s: float) -> dict` | Task 7 | 返回 decode_tokens、decode_seconds、decode_tps、tpot_ms；无有效 decode 时后两项为 None |

`SchedulePlan` 是 CPU 参考/调试结果；正式运行时 c/K/steal 为 device-resident 参数，不能返回 Python int 后逐层决策。生产接口用预分配输出与 workspace，custom op 同时提供 meta/fake 实现和明确的 alias/mutation schema。
