# Native Marlin dynamic CTA budgeting v1

The user approved coding after the feasibility answer on 2026-10-21. This supersedes the earlier diagnostic-first prerequisite. Objective: improve native SGLang throughput, retaining MXFP4 Marlin, shared experts, original prefill and CUDA Graph. This is a Weave-inspired resource scheduler, not the paper persistent communication scheduler.

## Execution
Patch only source-pinned Marlin in a private JIT overlay. Keep the native host selection algorithm and workspace capacity. Compiled candidate register attributes can change the selected tile, grid and shared-memory size relative to the unmodified binary; the physical grid is fixed within each captured graph. Never force an original grid that exceeds candidate occupancy. In the device kernel, compute a virtual worker count from existing GPU grouping: local live routed rows, total routed slots and local valid expert blocks, EP size and native grid. All stripe partitioning and lock-layout decisions use this virtual count. Inactive CTAs exit before accessing locks. Physical grid stays fixed across graph replays; runtime grouping changes the active count without CPU readback, graph rebuild, a new planner kernel, or CUDA event nodes.

The initial uncalibrated policy targets 75% of the native grid at balanced EP load, scales by local/total live route share times EP size, clamps to 25–100%, rounds up to eighth-grid buckets, and caps by available K/N/block iterations. Empty local work chooses zero. This controls active CTA budget, not an exact physical SM partition. Gate/up and down run the same policy with their own shape. Full mode preserves the native virtual count as a debugging/control option; it is not the unmodified baseline.

Pass a persistent per-layer/per-GEMM int64 evidence buffer (19 entries) through the patched FFI and kernel. Block 0 thread 0 writes a launch counter, last grouping/geometry and bucket histogram. No raw routing, content, logits or weights leave GPU/server. Read counters only at idle measurement boundaries; never sample the performance window. Install context at model/MLP forward before graph capture. Use original Marlin for prefill; require 43 layers and two calls per decode layer.

## Delivery and validation
No new external packages. Generate overlay from installed, hash-verified SGLang 0.5.17 sources and the repository patch. Existing Linux image supplies compiler. Server downloads only GitHub. Keep all installed package files unchanged and fail on source mismatch. Both baseline and adaptive arms use full CUDA Graph, C32 initial control and natural GPQA prompts/output, 1200 seconds each. Compare whole-window throughput and actual graph replay/counter coverage. Numerical/token differences remain record_only. Retain runtime, nonfinite, tensor/source/coverage/cleanup validity checks. CPU tests cover policy, partition/lock index safety, patch compatibility and controller contracts; GPU script compares original and patched real Marlin including changing routing under replay. Local CPU checks do not claim GPU success.

Ruling: native grouping combines remote -1 slots, so grouped-block ratio would be invalid. Each warp counts live local routes from the existing grouped arrays and uses that route fraction. No CPU transfer, extra planner kernel or CTA barrier is introduced.

Ruling: retain native register-aware configuration selection. Original geometry cannot be promised because the budget prologue can change registers; forcing original geometry can compromise split-K progress. Evidence reports the candidate launch grid and selected tiles.
